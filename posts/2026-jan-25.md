### Methodology
As with my work on rating analysis i get the information from e621.net json api. this time i queried for anything tagged with tom_fischbach.

Once i get the data from there and remove some useless information I store it as a json, which you can also get in [this same repo](data/2026/tom-2026-01-18.json) if you want to play with it youself.

Details on how this works are provided on this [repo README.md](../README.md) and should not change significantly over time so wont repeat it here. You can check that file out if you want an slightly more details on how these scripts work. 

At the end of the day the data is grouped per tags and per a period of time, usually a quarter and presented as a quaint little bar graph.

There are however two important changes this year:
1- Fixed the way i group data from each 3 months based on the starting date to: each actual quarter: Manuary-March, April-June, July-September, October-December
2- Added a heatmap which provides more accurate visualization of what i wanted, although i still leave the stacked bar charts in place.

Second change was done since stacked bar charts are a neat way to fit a lot of data in a single plot but unfortunately they naturally imply the addition of all categories sum to something important. Which is not the case here since several character may appear per piece.

## Character presence over time:
Following graph shows the number of times an specific character was mentioned in the tags of every artwork properly grouper per quarter.
Data prior 2015 was pruned to make it cleaner to see.

![Incidence over time](../results/graphs/tom_fischbach/january-2026/2026_01_tags_over_time.png)

Again this shows the number of times an artwork was tagged with each specific character. Any artwork may have one or more characters in it so despite what the structure of the graph may imply they will not sum to anything special. Also the date grouping is correctly based on yearly quarters

This graphs lets me show a lot of stuff at the same time but is not particularly clear and implies a lot of information that is hard to see. Hence this year i brought another type of graph. A heatmap. 

Has the same information but we now have one row for each character and the more intense the color the more times we saw this character in this period. you can use the colo bar to get an idea of the amount but due the nature of this is a more qualitative thing instead.

![Character heatmap](../results/graphs/tom_fischbach/january-2026/2026_01_heatmap.png)

The most interesting result here is how we real absolute Laura collapse, ever since we lost the tkpolls voting her presence has slowly retired from sketches and this year she was basically gone, in favor of a bit more Kat and more Keith.
